2. EXPERIMENTO: PRUEBA DE NEGOCIACIÓN CON VERSIÓN NO COMPATIBLE ('1999-01-01')
------------------------------------------------------------------------------------------------------------------------
Petición enviada:
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "1999-01-01",
    "capabilities": {},
    "clientInfo": { "name": "cliente-mcp-minimo", "version": "1.0.0" }
  }
}

Respuesta recibida del servidor:
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "protocolVersion": "2025-11-25",
    "capabilities": {
      "tools": { "listChanged": true }
    },
    "serverInfo": {
      "name": "secure-filesystem-server",
      "version": "1.0.0"
    }
  }
}

3. ANÁLISIS DEL COMPORTAMIENTO OBSERVADO:
------------------------------------------------------------------------------------------------------------------------
- El servidor MCP NO lanza un error JSON-RPC de protocolo (ni aborta la conexión stdio).
- En su lugar, el servidor responde con un objeto "result" estándar y propone su versión compatible más reciente (2025-11-25).
- Esto demuestra que la negociación de versiones en MCP se realiza de forma flexible a nivel de aplicación durante el handshake initialize, permitiendo al cliente evaluar si es capaz de interoperar con la versión ofrecida por el servidor o terminar la sesión si existiese incompatibilidad mayor.
